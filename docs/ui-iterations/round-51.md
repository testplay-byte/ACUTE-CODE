**Date:** 2026-08-30 · **Branch:** `main` · **Version:** 0.51.0 · **Owner directives:** every workstream in this round traces to the owner's fourth Windows test session after R50.

**What the owner confirmed working (frozen, untouched):** the composer overall ("built properly, exactly how I wanted it to be"), the Access/permission button ("perfect"), sub-agent live streaming ("They did stream their raw thinking and everything like that properly as I wanted them to be"), the donut's shape, the stats' content.

**The round's one big discovery.** "The browser was still not working properly" — for the fourth round in a row — was **not a browser bug**. The launcher runs `pnpm dev:full` and opens the **system browser** at `localhost:5173`, where `window.__TAURI__` is undefined → `isNativeBrowserAvailable()` is false → the owner has ALWAYS been on the R43 fetch-proxy iframe path; the R50 native Chromium child-webview browser only exists inside the Tauri shell, which had never been delivered (no installer — ADR-0003/0009 deferred it). So this round **delivers the shell**: a CI-built Windows NSIS installer with the bundled Node runtime + sidecar, a desktop-first launcher flow, and Credential-Manager key seeding. That is the real fix for the browser complaint — and everything else the owner asked for ships alongside it.

### R51-a — the desktop shell delivery (THE browser fix)

- **The staging decision (evidence, not assumption):** `pnpm --filter=agent-core deploy --prod` refuses without `--legacy`; with it, it stages 202 MB including the FRONTEND's node_modules and produces a tree that cannot boot (`shared`'s `main: ./src/index.ts` → Node type-stripping error — reproduced). So `scripts/release/stage-sidecar.mjs` (NEW) stages the sidecar the honest way: agent-core's built `dist/`, a pruned package.json with exact lockfile versions, a `pnpm install --prod` with its own workspace file (pnpm 11 `allowBuilds` map — the native addons build), and the vendored `shared` package with a patched runnable package.json. **The staged tree was proven to boot locally** (ACUITE_READY + `/health` 200, twice), including the exact CI invocation with `--platform win32-x64` pruning (301 → 216 MB).
- **The Rust release spawn** (`sidecar.rs`): `resolve_sidecar_command` picks (1) the `ACUTE_SIDECAR_CMD` override, (2) the RELEASE path — bundled `<resource_dir>/sidecar/node.exe` + `sidecar/app/dist/main.js` (cwd = the app dir, honest "broken install" error if the runtime is missing), (3) the dev repo-walk, byte-identical to before. `provider_key_targets()` now injects the sub-agent pool keys too (`ACUTE_PROVIDER_OPENROUTER_SLOT2/3/4` from Credential Manager services `openrouter-slot2/3/4`) — pool keys survive restarts in the packaged app. Every new signature was audited against the fetched tauri 2.11.5 sources (`Manager::path`, `PathResolver::resource_dir`, the resources-map semantics from tauri-utils tests, NSIS `NsisConfig` fields, the NSIS template's registry keys/filename/silent flags, `mainBinaryName`).
- **The bundle** (`tauri.conf.json`): `bundle.active` with `targets: ["nsis"]`, `icons/icon.ico`, resources `{"staging/sidecar/": "sidecar/"}`, `installMode: "currentUser"` (no admin), and `mainBinaryName: "ACUTE-CODE"` (unset would produce `acute-code.exe` — the spec's assumption corrected against the CLI source). The window also gained `minWidth: 1000 / minHeight: 620` (the owner's "should not be allowed to shrink more than a specific limit" — the OS-level half of the fix; the composer-level half is R51-c's).
- **CI** (`release.yml`): a new `desktop-installer` job (windows-latest, 30 min timeout): Node 24.20.0 **pinned = the bundled runtime** (the tested runtime IS the shipped one), Rust stable + cache, build → stage → download the Node zip (node.exe + LICENSES for the compliance folder) → `pnpm tauri build` → the NSIS artifact `ACUTE-CODE_<v>_x64-setup.exe` uploads as `acute-installer-windows-x64`; the release job now needs BOTH jobs and attaches kit + installer to the draft release, verifying the installer filename's version against the tag.
- **The launcher goes desktop-first** (`acute_launcher.py`, +~380 lines): on Windows the default flow now queries the latest release (PAT-authenticated, draft-aware), downloads the installer with progress, installs **silently** (`/S` — the NSIS silent flag, verified in the template), **seeds the owner's keys into Credential Manager** via `cmdkey` (main + slots 2–4, values never logged), and launches the installed `ACUTE-CODE.exe` (found via the HKCU uninstall registry key — `InstallLocation` + `DisplayVersion`; three candidate keys probed). EVERY failure falls back to the untouched dev-servers flow; `--web` forces it; a `desktop` command and `status` visibility included.
- **BrowserPanel honesty:** a native-mode create failure now **flips the panel into the proxy renderer** with the explanatory error card ("Native browser unavailable (…) — fell back to the proxied renderer") instead of a dead end, and the status footnote became a visible **engine badge** — "Chromium (native)" / "Proxy fallback" — so the owner can SEE which engine is live (the round's discovery made observability non-negotiable). Tests 19→22.

**Honest risks (CI is the only oracle for the Rust + the NSIS build):** first `pnpm tauri build` on a fresh runner downloads NSIS tooling and ships a 216 MB resource tree — inside the 30 min timeout but slow; the installer is unsigned (SmartScreen will warn; signing is a future workstream); the desktop flow needs this round's release to actually exist (the launcher falls back gracefully until then).

### R51-c — the composer polish, clause by clause

- **Add Context is just the paperclip** (the "Context" text is gone; aria-label + tooltip kept). **The model button shows only the model id** (the provider moved to the tooltip).
- **The model flyout can no longer be cut off:** hovering a provider row now MEASURES row + popover + viewport and computes the flyout's side, clamped vertical position, and max height through a pure, unit-tested `computeFlyoutGeometry` helper. The flyout renders `position: fixed` (viewport coordinates) — a documented deviation REQUIRED by the same spec's popover max-height: an absolutely-positioned flyout inside a scrolling popover is the classic dropdown-in-scroller clipping bug. The popover itself gained a viewport-capped max-height + scroll (many providers can no longer overflow), and the flyout was restyled (provider-name header chip with model count, rounded hover rows, the hidden-paid hint as a proper footer).
- **The donut:** the inline `%` label next to the toolbar ring is GONE (the percentage lives in the popover + the button title); the popover now **stays open while you move into it** — a shared ~220ms close timer bridges the trigger→popover gap (the owner's exact complaint), with click-to-pin and focus/blur keyboard behavior; the ring color grades by pressure (accent → amber at 60% → red at 85%, thresholds exported for tests).
- **The stats split:** `GET /sessions/:id/context` now ALSO returns `usage: { main, subagents, combined }` (each inputTokens/outputTokens/requests/costUsd) — subagents aggregates the usage_events of the session's DIRECT children (grandchildren excluded, listSubAgents parity), the flat sessionTotals fields stay byte-identical for every other consumer. The popover renders Main agent / Sub-agents / Combined groups. **Live battery proof:** after a real delegation, `sub=6155in > 0, combined=30170in > main=24015in`.
- **No more overlapping controls:** both toolbar clusters are `shrink-0` with a collapsing spacer between them, and the toolbar wraps to two rows only when one row cannot hold both clusters — the left and right controls can never render at the same x-coordinates (verified at 400/560/900px mental widths + jsdom invariants). Composer tests 28→46.
