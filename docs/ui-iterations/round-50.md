### R50-a — the native embedded browser (Chromium, inside the app window)

**The architecture decision.** The R43 fetch-proxy iframe could never be a real browser — tickets expire, sub-resources fight the rewriter, service workers and CSP-heavy sites break. The owner asked for "a proper full-fledged browser… Chromium as the base". On Windows, Tauri's WebView2 IS Chromium (the same engine as Edge) — so instead of shipping a Chromium fork, every browser tab is now a **child webview hosted inside the main app window** (Tauri multiwebview): positioned exactly over the BrowserPanel's page area, rendering with the full real browser engine. No proxy, no tickets, no URL rewriting — CSS/JS/service workers just work, because it IS the browser.

**The Rust surface** (src-tauri/src/browser.rs, +346 lines): `browser_tab_create` (idempotent create-or-navigate; creates the child webview hidden at 1×1, `data_directory` = the shared `browser-profile` dir so logins persist across launches and tabs share cookies like a real browser), `browser_tab_navigate`, `browser_tab_set_bounds` (logical px == CSS px of the main webview), `browser_tab_set_visible` (tab switch = hide, session stays alive), `browser_tab_go` (back/forward/reload through the page's own history), `browser_tab_url`, `browser_tab_close`, `browser_tabs_close_all`. Every navigation fires a `browser-navigated {tab_id, url}` event to the frontend (the `on_navigation` hook), so the address bar and the sidecar's server-side history stay truthful for the `browser_control` agent tool.

**Enabling it required `tauri = { features = ["unstable"] }`** in Cargo.toml — `Window::add_child` is feature-gated in tauri 2.11.5 (verified against the crate source fetched to /tmp before any Rust was written: window/mod.rs:1129 `#[cfg(any(test, all(desktop, feature = "unstable")))]`). Every other signature was verified the same way (`WebviewBuilder::{data_directory, on_navigation}`, `Webview::{set_position, set_size, hide, show, eval, url, navigate, close}`, `Manager::{get_webview, webviews}`). One further source-verified subtlety: `browser_tab_create` is an **async** command — `add_child` blocks on a channel to the main thread, and tauri's own WebviewBuilder docs warn that a SYNC command calling it deadlocks on WebView2 (wry#583).

**The frontend** (BrowserPanel.tsx + the new src/lib/native-browser.ts bridge): when running inside Tauri, the page area is a placeholder `<div>` whose `getBoundingClientRect()` is continuously synced to the webview bounds (ResizeObserver + window-resize + a 500 ms safety net, rAF-debounced) via a pure, unit-tested `computeNativeBounds` helper (viewport presets letterbox + center; the natural mode fills the panel; zoom scales the bounds). Address-bar submits drive BOTH the server history (the agent's `browser_control` stays truthful) and the native webview; the 4 s server poll reconciles agent-driven navigations into the webview; user link-clicks (`browser-navigated` events) fold back into the server history with an echo-suppression `lastCommandedUrl` guard. **The iframe-proxy path is untouched** as the non-Tauri fallback (web dev + e2e) — all 10 pre-R50 BrowserPanel tests pass verbatim.

**Honest limitations, documented in-code:** zoom is bounds-scaling (not a browser zoom factor); DPI ≠ 100 % assumes logical-px equivalence (needs the owner's Windows smoke test); all tabs share one WebView2 profile dir (the per-tab-subdir fallback is documented in browser.rs if WebView2 ever objects). The R41 pop-out window commands remain registered (the panel's "Open externally" affordance).

### R50-b — sub-agents stream their raw thinking/text LIVE (+ retries + stats)

**Root cause of "no raw stream":** children ran the SYNC turn path (`runSingleAgentTurn` → `generateText` + step snapshots). Fix: `chatStream` now flows into `toolDeps`, and the orchestrator runs children through `runStreamedAgentTurn` when a channel exists — the child's `text-delta`/`thinking-delta`/`tool-call`/`tool-result`/`finish` events ride the parent's SSE as `subagent-event` envelopes, exactly like the main agent's own stream. Channel-less runs (the plain sync route) keep the R48 fail-fast ask semantics — the security posture is unchanged.

**Root cause of "failed after three attempts":** the AI SDK's default `maxRetries: 2` (3 total attempts) — precisely the three the owner counted. Both adapters now pass `maxRetries: 4` = **5 total attempts** with the SDK's exponential backoff.

**The stats footer** (pinned at the bottom of the Sub-agent panel's live view, the owner's exact five): total time (a live m:ss/h:mm:ss clock), tokens sent ↑, tokens received ↓, tokens/sec (↓ ÷ elapsed, live), and the model. Live values come from the store's accumulators (inner `finish` events carry usage); after completion they hand off to the authoritative `/subagents` row (which now carries `model` from the child's latest usage row). Reset rule: a `running` status frame clears the current attempt's text/thinking accumulators (a retry restarts cleanly) but NEVER the token counters (SUM semantics — live→final handoff is monotone).

**Live proof (the owner's exact scenario, run in this round's battery):** a delegation turn produced **308 `subagent-event` frames — 75 child text-deltas + 218 child thinking-deltas streaming live through the parent's SSE** — and the child wrote `battery-r50.md` on disk; the row read `IF8P role=coder status=completed in=48564 out=740 model=z-ai/glm-5.2:free`.

### R50-c1 — the composer backend (contracts + enforcement)

- **Permission modes** (migration 0020: `sessions.permission_mode` default `'ask'`): `PATCH /api/v1/sessions/:id/permissions` with mode ∈ **full | ask | plan | editor**. Enforcement in `prepareTurn` via `sessionToolAllowList` (shared by the context meter so both agree by construction): *plan* intersects the tool set down to the 12 read-only/research tools (no file mutation, no run_command, no index_project); *editor* keeps every file tool but strips `run_command` entirely (deletes keep their ask semantics); *full* keeps the whole toolset and auto-approves every ask-tier gate (non-auto commands, non-allowlisted web/browser hosts) — while the **denylist-supreme refusals (sudo/rm -rf/…) are never bypassed in ANY mode and agent allowlists stay authoritative** (a mode only widens within the agent's own allowed tools). Children copy the parent's mode at delegation; the system prompt gains a PERMISSION MODE section describing the active mode.
- **Thinking levels** (per-send like the model override, NOT persisted): `thinkingLevel` ∈ **default | low | high | max** on both send routes → threaded through both turn runners → `buildThinkingFetch` wraps the provider fetch and injects `"reasoning": {"effort": …}` into the outgoing JSON body (merge-not-clobber, composes over the OpenRouter `:free` fallback rewriter; anthropic-messages/responses formats skip it — honest limitation, documented). Live proof: the battery's turn with `thinkingLevel=low` streamed **246 thinking-delta events** and completed normally.
- **Attachments**: `POST /api/v1/attachments/read` (≤20 paths; 128 KB head with `truncated`; NUL-sniff binary → no text; relative paths resolve only inside the project root — escapes rejected per-file; absolutes read as-is) + the multi-file OS pickers (`pick_files` Rust command mirroring the R48 parented/topmost `pick_folder`, plus the sidecar PowerShell `OpenFileDialog` Multiselect fallback at `POST /api/v1/internal/dialog/files`) + `pickFilesViaBackend()` in api.ts. Send routes accept `attachments` (≤20, name ≤200 chars, text re-capped server-side), persist them on the `message.user` event, and `assembleHistory` renders each one into the model-facing content as `--- attached file: … ---` blocks. Live proof: the battery's attachment turn — the model read the fixture's content in its thinking and answered "The fixture says 'ACUTE-CODE R50 live battery says hello.'"
- **The context report** (`GET /api/v1/sessions/:id/context?model=`): contextWindow (models row → catalog → 200k), usedTokens, and the breakdown the owner listed — **messages, system prompt, system tools (the prompt's tool section + ~350 tokens/tool schema approximation), memory & skills, meta, MCP tools (honest 0 — no MCP system yet)** — plus **cache** (inputTokens, cachedInputTokens, hitRate) and **sessionTotals** (requests, tokens in/out, costUsd). The cache numbers are REAL: `usage_events.cached_input_tokens` (migration 0020) captures `usage.inputTokenDetails.cacheReadTokens` — OpenRouter's `prompt_tokens_details.cached_tokens` — on both turn paths. Live proof: the battery's first run recorded cachedInputTokens=128 with hitRate 0.007 from a real provider response.
- prompts.ts was minimally refactored into `buildSystemPromptSections` (identity/tools/memory/meta) — `buildProjectSystemPrompt` composes from it with byte-identical behavior (all pre-existing prompt tests green).

### R50-c2 — the composer UI (the owner's spec, clause by clause)

The old bottom bar + ComposerFooter are gone. The composer is now a family of 12 files under `src/components/project-chat/composer/`:

- **Empty state (A):** a fresh chat renders the composer centered, pushed below the middle (45/55 flex spacers — reflows, never absolute), suggestion chips above it; once a conversation exists it docks to the bottom.
- **One box, toolbar inside (B):** radius-18 warm-background box (the R32 visual language, accent glow on focus) = auto-growing textarea + attachment chip row + a `role=toolbar` row INSIDE: left `[Add Context] [Mode]`, right `[Donut] [Model] [Thinking] [Send]`.
- **Add Context (C):** menu with *Attach files…* (the real Windows picker → `readAttachmentFiles` → chips), *Add project files…* (searchable multi-select over the project tree), and an **@-mention quick-picker** (typing `@` filters project files live above the caret; Enter/click attaches and strips the token). **Drag-and-drop** reads dropped files client-side (FileReader, 128 KB, NUL-sniff → "no text" chip) with a drop-highlight state. Chips show name + size + ✕ + truncated badge; ≤20 cap with honest partial-failure toasts.
- **Mode switcher (D):** segmented dropdown (Zap/ShieldCheck/ClipboardList/FileEdit) with the four spec-exact descriptions; changing mode PATCHes the session with an optimistic cache update, rollback + toast on failure.
- **Thinking level (E):** Brain button with exactly Default/Low/High/Max; persists per session (`acute-thinking:<id>`), rides every send.
- **Model selector (F):** the button shows `ProviderLabel · full-model-id`; clicking opens the providers popover (NOT a model list): one row per added provider, **hover → flyout of that provider's models on the side with space** (measured; inline fallback on narrow widths), checkmark on the effective model, a Free-only/All toggle (the shared persisted preference), a Configure gear per provider, and the **Manage Models footer → `/settings?tab=api`**. The override persists per session (`acute-model:<id>`) and survives remounts.
- **Context donut (G):** a 22 px SVG donut in the toolbar (fill = used/window from `fetchSessionContext`, refetching on transcript changes, 30 s staleTime); hover/click opens the detail popover — big donut + % used + used/window, six mini-bar breakdown rows (MCP honestly "none configured"), the cache hit-rate line, and the SESSION section (Requests, ↑, ↓, Cost).
- **Send (H):** accent button, disabled when empty/busy, Enter-to-send + Shift+Enter newline, the existing Stop semantics untouched.

The send payload is `{content, model?, thinkingLevel?, attachments?}` on both paths (the stream store + `useSendMessage` thread the extras through — additive, old callers byte-compatible).

## Honest limitations & what needs the owner's Windows machine

1. The Rust compiles by construction against the fetched tauri 2.11.5 source but **CI's `cargo check` is the only Rust compiler in the loop** — the child-webview surface (create/bounds/show/hide/navigation events) needs a Windows smoke test, especially DPI ≠ 100 % bounds alignment and multiple tabs sharing one profile dir.
2. Thinking-level injection is chat-completions-only (the OpenRouter path); anthropic-messages/responses formats ignore it (documented in chat.ts).
3. Context-meter breakdown numbers are honest approximations (estimateTokens ~4 chars/token; tool schemas ~350 tokens/tool); MCP is reported as an honest 0/none.
4. Zoom in the native browser is bounds-scaling, not a browser zoom factor.
5. The sub-agent HTTP retry route (POST /subagents/:childId/retry) still runs the sync path — its streamed branch is wired and waiting for a channel-backed caller.
