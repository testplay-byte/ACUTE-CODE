## Cross-cutting synthesis

1. **Our core architecture is the field's convergence point.** Every reference now runs "UI client ↔ local agent server owning SQLite": Cline's hub-spoke + Tauri example, OpenCode's Effect server + generated client, Kilo's `kilo serve` (a fork of OpenCode), Goose's desktop↔`goosed`, OpenHands' headless Agent Server. Five independent validations of the SPEC's Tauri-shell + Node-sidecar decision. Concrete mechanics to adopt: sidecar binds ephemeral port + reports via stdout ready-line (goose race-fix), per-launch bearer token with `timingSafeEqual` (cline), cursor-replay event resubscription (openhands).
2. **Memory: markdown as source of truth, bounded, injected as a frozen snapshot.** Hermes (MEMORY.md/USER.md + FTS mirror, snapshot injection protecting prompt cache and injection-resistance) and Letta (budgeted blocks + history audit; new git-backed markdown direction) both validate SPEC F8. Letta's `block_history` audit table and Hermes' staged/approved writes feed the approval engine design.
3. **Skills: SKILL.md folders with progressive disclosure are the universal standard** (Hermes self-authored with security scanning; Kilo project/global scopes, metadata-only until invoked) — matching the owner's v1 skills decision (SPEC F8).
4. **Orchestration: delegation-as-task-tool won.** Kilo deprecated dedicated orchestrator modes for a plain `task` tool (isolated child context, summary-only return); OpenHands implements the same (`TaskToolSet`, resumable sub-conversations); MetaGPT's typed pub/sub pool remains the best shared-bus model. For ADR-0001's auto-team: orchestrator plans on the bus, delegates via task tool, workers return structured summaries; topology as data.
5. **Approvals: layered, denylist-supreme, auditable.** Consensus design across hermes (hardline floor), kilocode (allow/ask/deny globs, last-match-wins), opencode (regex command filters + permission round-trip endpoint), openhands (typed confirmations with `respond_to_confirmation`), goose (remembered grants keyed `tool:hash(args)`), cline (per-tool auto-approve + version field against races), aider (`allowed_to_edit` gate). SPEC F6 is exactly this intersection; add openhands' security-risk fields on actions and goose's arg-scoped grants at Phase 3 design. Cline's permissive defaults (`executeAllCommands: true`) are the anti-example — we stay fail-closed.
6. **Storage: SQLite WAL owned by the server process, append-only session events.** Kilo (`kilo.db`, WAL, Drizzle), goose (sessions/messages/usage_ledger), hermes (single-writer + FTS5), opencode (Drizzle migration from JSON files — the JSON-sprawl cautionary tale), letta (SQLite default). OpenHands V1 uses locked JSON files (their V0→V1 lesson: event-stream complexity, not storage choice, was their pain point) — SQLite remains right for us. Adopt per-request usage rows (goose/hermes) and seq-numbered append-only events (openhands/kilo).
7. **Editing reliability: an application ladder with structured errors beats hoping.** Aider's exact→whitespace→elision ladder, `SearchReplaceNoExactMatch` with did-you-mean feedback, `max_reflections=3`; cline's diff strategies + checkpoints; kilocode's git-backed snapshots. Phase 4's file-edit tool follows this recipe.
8. **Recurring anti-patterns to avoid** (cited across memos): permissive-by-default approvals (cline), fail-open security gates (goose OSV), monolithic core files (hermes' 560 KB `run_agent.py`), secrets in config files, storage sprawl (opencode pre-migration), tool-count bloat, keys in WS query params (openhands V1 does it; we use a first-message auth frame per ADR-0008), and mirroring any vendor's API verbatim (letta blocks are being replaced by their own admission).
